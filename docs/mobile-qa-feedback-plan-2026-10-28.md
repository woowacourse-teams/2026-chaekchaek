## 서버 계약 재확인 결과

- [운영 OpenAPI](https://api.chaekchaek.com/docs/openapi3.yaml), [개발 OpenAPI](https://dev-api.chaekchaek.com/docs/openapi3.yaml)를 이번 조사에서 다시 조회했다. 검색 sort와 프로필 사진 업로드 계약은 찾지 못했다.
- 개발 서버 `query=어린&page=1`의 LATEST·COMMENT 요청은 같은 ISBN 순서를 반환했다. 감상 수가 1,2,0인 책이 순서대로 유지돼 감상 수 내림차순이 아니다.
- 오래된 `feature/book-search-sort` 브랜치에 정렬 계약이 있었지만 최신 배포 계약의 근거가 아니다. 서버 구현과 노출 UI를 함께 맞춰야 한다.
- BE 최신 MemberController는 GET me, PATCH nickname/anonymity, DELETE me를 제공한다. 사진 업로드를 기존 nickname API 등에 임의로 실어 보내지 않는다.
- 사진 변경 API의 필드·파일 제한·저장 위치·원본/선택 사진 구분·기존 사진 전환은 서버 변경 설계가 필요하다. 기존 사진의 출처를 판별하지 못한 채 새로 선택한 사진까지 지우지 않도록 이전 범위를 검증한다.
- 정렬·이용 불가 도서 제외·사진 저장의 BE 변경은 모바일 스코프 밖이다. 서버 계약 복구·추가 범위를 합의한 뒤 BE 전용 브랜치와 검증으로 진행한다.
