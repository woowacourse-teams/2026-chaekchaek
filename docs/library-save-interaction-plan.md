# 서재 저장 상태와 홈·피드 바로 담기

## 목적과 상태

- 사용자가 책을 저장한 사실을 나중에도 알아보고, 홈·피드의 감상에서 책만 바로 저장할 수 있게 한다.
- 관련 이슈: [#527](https://github.com/woowacourse-teams/2026-chaekchaek/issues/527)
- 사용자 합의일: 2026-10-16
- Figma와 공유 Compose 구현을 반영했다. 아래 완료 기록에서 자동 테스트, Simulator 검증과 미검증 항목을 구분한다.
- 작업 PR: [#528](https://github.com/woowacourse-teams/2026-chaekchaek/pull/528), 기준 `an-develop`
- 적용 대상은 `android/` 안의 Android·iOS 모바일 앱이다. 백엔드와 웹 프론트엔드는 이번 범위에 포함하지 않는다.

## 여러 책장 전환 (2026-10-23, #608)

이 절은 아래 2026-10-16의 단일 서재 동작보다 우선한다. 작업 PR은 [#609](https://github.com/woowacourse-teams/2026-chaekchaek/pull/609)이다.

- 최신 Swagger 계약은 `android/openapi3.yaml`이다. 사용자가 제공한 계약을 기준으로 구현했다. 확인 당시 운영 Swagger에는 `/api/v1/libraries`가 없어 운영 서버 연동은 배포 전제다.
- 내 서재는 여러 책장 목록과 단일 책장 상세로 구성한다. 책장 생성, 이름 변경, 기본 책장 외 삭제, 책 배치 삭제, 책장과 책의 순서 저장을 지원한다.
- 책장 이름은 공백만으로 만들 수 없으며 1-10 UTF-16 길이로 제한한다. 동일 회원의 대소문자를 구분하지 않는 중복 이름을 금지한다. 기존의 긴 이름은 편집 전까지 보존한다. 책장 수 제한은 없다.
- 담기 버튼은 이미 저장된 책에도 활성화한다. 담기를 누르면 회원별 최근 저장에 성공한 책장을 선택한 시트를 열고, 사용자가 책장을 확인하거나 바꾼 뒤 확정한다. 최근 책장이 사라졌으면 기본 책장을 선택한다. 임시 책장은 만들지 않는다.
- 같은 책을 여러 책장에 둘 수 있으나 같은 책장 안에 중복 배치할 수 없다. 책장당 30권을 넘겨 추가할 수 없다. 이전 데이터가 이미 30권을 넘겼어도 조회와 순서 저장에서 자르지 않는다.
- 비로그인 담기는 `책을 담으려면 로그인이 필요해요.`로 안내하고 로그인 후 책장 선택을 이어간다. 저장 실패 시 입력과 선택을 보존하며 기존 공통 오류 정책의 복구를 사용한다.
- 첫 책 온보딩은 기존 흐름과 `/api/v1/library` 기본 책장 저장을 유지한다. `LIBRARY_ITEM_ALREADY_EXISTS`만 중복 성공으로 취급한다. 회원가입 기본 책장 생성과 기존 사용자 데이터 이전은 백엔드 책임이다.
- 이미지는 단일 책장과 소유자 책 순서를 보존한다. 책마다 `MINE` + `LATEST` 감상 중 삭제되지 않은 최신 1개를 넣는다. 감상이 없으면 해당 영역을 빈 플레이스홀더로 유지한다. Android는 PNG 파일 저장 선택기와 이미지 공유, iOS는 사진 저장과 네이티브 이미지 공유를 사용한다. 링크 공유 정책은 이 작업 범위에 없다.
- 질문 반응은 `good`, `heart`, `think`, `calm`, `sad` 5개다. 별 반응은 제거한다. 기존 서버 미연동 질문 프리뷰의 범위는 그대로이며 반응 API를 새로 가정하지 않는다.

### 구현 및 검증 경계

- `BookshelfRepository`는 책장과 배치를 맡고 독서 기록 및 별점 수정은 기존 저장소에 둔다. `BookshelfViewModel`은 추상 계약을 주입받는다. 기존 `ArchiveViewModel`의 구체 저장소 의존(DIP 위반)은 내 서재의 실제 호출 경로에서 제외했다. 기존 `BookDetailViewModel`의 같은 제약은 이번 작업에서 전체 리팩터링하지 않았다.
- 단위 테스트는 인증, 전체 순서 ID, 같은 책장 중복과 용량, 회원별 최근 선택, 실패 시 선택 보존, 최신 본인 감상 선택과 빈 감상을 다룬다. 합성 서버는 기존 35권 책장과 추가 실패를 재현한다.
- Figma A안과 책장 선택 시트 `1585:6342`, 반응 컴포넌트 `1416:5812`, 이미지 공유 화면 `1346:4874`를 조회하고 상태를 확인했다. Figma 반영과 앱 실행 검증은 별도다.
- `3c6060ee`의 Android host 공통 테스트 427개를 통과했다. 실패, 오류, 건너뜀은 0개다. 필수 `status`가 직렬화에서 빠지던 문제를 수정하고 요청 본문 검증을 추가했다. 합성 서버도 필수 상태 누락을 거부한다.
- 같은 커밋의 iOS Simulator 빌드와 `BookshelfContractUITests` 1개를 통과했다. iPhone 17 Pro 유형, iOS 26.2, 기본 글자 크기에서 이름 변경, 생성, 책 추가, 배치 삭제, 사진 저장과 네이티브 공유 메뉴 표시를 확인했다. 실제 요청의 `status: READING`도 대조했다.
- iOS의 저장 PNG 전체를 열어 소유자 책 순서, 감상이 없는 책의 빈 영역과 최신 본인 감상 1개를 확인했다. 절반 높이 시트의 확정 버튼 가림을 수정했고, 배치 변경 후 상세 갱신 중 오래된 이미지 생성을 막았다.
- Android 앱과 계측 APK 빌드, 패키지·버전·서명 비교 및 데이터 보존 설치는 통과했다. 기존 AVD의 Portal 설치는 공간 부족으로 실패했다. 캐시 정리 후 재시도에서도 동일하여 Jev 트리 검증은 미완료다. 기존 사용자 데이터 삭제나 다른 AVD 생성은 수행하지 않았다.
- Android `7e176d36`의 실제 계측에서 이름 변경, 생성, 책 추가와 배치 삭제 시나리오 1개를 통과했다. 이미지 시나리오는 네이티브 파일 저장과 성공 안내까지 실행한 뒤 선택적 화면 캡처가 null을 반환해 실패했다. 저장된 PNG 전체를 열어 책 순서, 최신 감상과 빈 영역을 확인했다. 이후 앱 변경은 공유 버튼의 검증용 testTag 추가이며 기능 로직은 동일하다.
- 선택적 캡처를 수정한 뒤 같은 AVD에서 재시도했지만 합성 서버 NAT 연결 시간 초과가 발생했다. `41d62553`은 ADB reverse와 로컬 `127.0.0.1:19068` 설정으로 빌드·서명 비교·데이터 보존 재설치까지 성공했으나 Android가 앱 프로세스에 계측을 연결하지 못했다(`failed to attach`). 당시 Android 전체 계측 통과와 네이티브 공유 메뉴 표시는 미검증으로 남겼다. 이 환경 실패를 기능 통과로 계산하지 않는다.
- 2026-10-23 후속 Android 검증: `1d9d6ed8`의 공유 전용 계측 1개가 7.527초에 통과했다. 동일 `Pixel_6a_API_33_2`, API 33, `emulator-5590`에서 데이터 보존 콜드 부팅과 호스트 GPU를 사용했다. 실제 앱의 책장 상세에서 공유 시트를 열고 새 PNG 생성과 시스템 공유 창을 확인했으며, 시스템 로그의 `ChooserActivity` 표시도 대조했다. 공유 PNG는 936x2618이며 소유자 순서, 최신 감상 1개와 감상이 없는 빈 영역을 유지한다. 공통 host 테스트 427개도 통과했다. 공유 성공 경로는 확인했으나, `6871fc71`의 캡처 안정화 재실행은 공유 시트 준비 조건에서 30초 시간 초과로 실패했다. 최종 반복 실행의 안정성은 미확인이다. 전체 계측 3개의 일괄 통과나 Jev 완료를 뜻하지 않는다.
- 합성 서버 검증은 운영 서버 연동과 구분한다. 실제 운영 인증·저장, 백엔드 기본 책장 생성과 데이터 이전, 스토어 배포는 검증하지 않았다. 책장·책의 전체 ID 순서는 단위 테스트로 검사했으며 실제 드래그 제스처 전체 검증이나 접근성 감사 완료를 뜻하지 않는다.

## 합의한 사용자 동작

사용자가 홈·피드의 감상 카드에서 책을 선택해 저장하면, 감상을 작성하거나 책 상세로 이동하지 않고 같은 자리에서 저장 결과를 확인한다.

| 조건·행동 | 기대 화면·결과 | 데이터·상태 변화 |
| --- | --- | --- |
| 미저장 책 확인 | 책 정보 영역에 `+ 서재에 담기` 표시 | 저장 여부 조회 |
| 담기 선택 | 현재 화면과 스크롤 위치 유지 | 책 저장 요청, 처리 중 중복 요청 차단 |
| 저장 성공 | 배경과 문구를 `✓ 담았어요`로 변경하고 `내 서재에 담았어요` 알림 표시 | 같은 책의 다른 카드, 책 상세와 내 서재에 결과 반영 |
| 저장 실패 | 기존 상태를 유지하고 실패 안내와 재시도 경로 제공 | 성공 상태로 확정하지 않음 |
| 저장된 버튼 재선택 | 저장된 상태 유지 | 삭제 요청을 보내지 않음 |
| 책 상세의 명시적인 `서재에서 삭제` 메뉴 선택 | 저장과 구분된 삭제 경로 사용 | 기존 삭제 정책을 확인하고 관련 화면에 결과 반영 |
| 다른 콘텐츠를 둘러본 뒤 복귀 | 저장된 책은 `✓ 담았어요`로 표시 | 기존 저장 결과 유지 |

- 홈·피드의 버튼은 좋아요와 구분해 책 제목·표지 영역에 둔다.
- 책 상세의 저장 버튼에도 같은 저장 전후 표현과 재클릭 정책을 적용한다.
- 저장 과정에서 감상 펼침 상태나 목록을 불필요하게 초기화하지 않는다.
- 기존 로그인 요구와 책 등록 시 독서 상태의 의미는 유지한다. 실제 인증·저장 호출 경로와 최신 API 계약은 구현 전에 대조한다.

## 구현 순서와 기준

1. [책췍 Figma](https://www.figma.com/design/tn59Thk2GRcVLkzoO8k9Sr)의 홈·피드·책 상세와 [디자인 시스템](https://www.figma.com/design/tn59Thk2GRcVLkzoO8k9Sr?node-id=1201-826)을 조회한다.
2. 저장 전후, 요청 중, 실패 상태를 설계한다. 공통 컴포넌트와 [컨트롤 레퍼런스](https://www.figma.com/design/tn59Thk2GRcVLkzoO8k9Sr?node-id=905-153)의 인스턴스 연결과 캡처를 확인한 뒤 코드에 적용한다.
3. 기존 등록·삭제, 인증과 화면별 저장 상태의 원본을 추적한다. 저장 의도와 삭제 의도를 분리하고 동일한 책의 요청 중복과 상태 동기화를 처리한다.
4. 공유 코드와 플랫폼별 진입점을 확인하고 Android와 iOS에서 같은 시나리오를 검증한다.

## 검증 계획

- 저장 후 다른 감상을 읽고 돌아왔을 때 버튼을 다시 누르지 않고 저장 여부를 구별할 수 있는지 확인한다.
- 홈·피드에서 상세 이동이나 감상 작성 없이 책만 저장하고 내 서재에서 확인한다.
- 저장된 버튼 재선택이 삭제를 요청하지 않는지 확인한다.
- 같은 책의 여러 카드, 상세와 서재가 같은 상태인지 확인한다.
- 저장 중 연속 클릭, 저장 실패와 재시도 시 요청 수와 표시 상태를 확인한다.
- 기존 인증 요구, 인증 취소·복귀 경로와 현재 화면의 스크롤·감상 펼침 상태가 유지되는지 확인한다.
- Android와 iOS의 빌드·자동 테스트·실제 실행 결과를 나눠 기록한다. 실행하지 못한 항목은 사유와 함께 미검증으로 남긴다.

### 코드와 데이터 흐름

- `LibrarySaveViewModel`은 홈·피드의 책 저장 요청, 인증 대기·취소, 중복 요청 차단과 실패 재시도를 맡는다. 저장 여부 자체는 `ArchiveViewModel`의 ISBN별 서재 목록을 사용한다.
- 성공 응답의 `bookId`와 `LibraryRecord`로 공통 서재 상태를 즉시 갱신하고 목록을 재조회한다. 재조회 실패로 이미 확인한 저장 결과를 되돌리지 않는다. 이전 인증 세션의 지연 응답은 새 세션 상태에 반영하지 않는다.
- 상세 저장은 `addToLibrary`, 삭제는 `removeFromLibrary`로 분리했다. 저장된 버튼 탭은 삭제나 카드 이동을 호출하지 않는다. 삭제는 `서재 관리 > 서재에서 삭제`와 기존 확인 다이얼로그를 거친다.
- 홈·피드의 버튼은 별도 클릭 대상으로 감상 작성이나 상세 이동을 호출하지 않는다. 홈 콘텐츠의 저장 가능한 상태를 유지하며, 로그인 재조회 때 이미 처리한 맨 위 이동 요청을 반복하지 않는다. 피드의 목록과 스포일러 펼침 상태 소유권은 유지한다.
- 500ms 이내 완료되는 요청에는 로딩 인디케이터를 표시하지 않는다. 요청 차단과 `담는 중` 표시는 탭 직후 적용한다.
- 원격 OpenAPI와 `android/openapi3.yaml`을 대조해 동일함을 확인했다. 기존 책 등록·서재 삭제 API와 인증 흐름을 재사용하며 API 계약이나 독서 상태를 변경하지 않았다.
- 독립 리뷰 후 동일 회원의 토큰 갱신에서는 서재 목록을 유지하고 로그아웃·새 로그인에서만 초기화한다. 조회 작업과 쓰기 작업을 분리해 바로 담기와 재조회가 진행 중인 일괄 삭제·상태 변경을 취소하지 않는다.
- 로그인 직후 기존 저장 목록을 아직 읽지 못한 경우, 서버가 `LIBRARY_ITEM_ALREADY_EXISTS`로 응답하면 회원 상세의 기존 기록을 확인해 저장 상태를 복구한다. `TOTAL_PAGES_CONFLICT` 등 다른 오류는 성공으로 처리하지 않는다.
- 바로 담기가 상세 조회와 겹치면 완료된 저장 기록을 열린 상세에도 전달한다. 저장 전에 시작한 상세 응답이 나중에 도착해도 확인된 기록을 지우지 않으며, 독서 상태·쪽수·별점 수정에서 중복 등록하지 않는다.
- 상세는 관찰을 시작한 뒤 완료된 저장만 전달받는다. 새 상세 진입에 과거 저장 결과를 재전달하지 않아 이후 수정한 쪽수·별점·독서 상태를 오래된 기록으로 덮지 않는다.
- 홈의 맨 위 이동 요청 번호와 처리 번호를 모두 저장 가능한 상태로 유지해 화면 복원 후 첫 탭 요청을 무시하지 않는다.
- 객체지향 관점의 기존 제약: `ArchiveViewModel`과 `BookDetailViewModel`은 추상 저장소 계약 대신 구체 RemoteRepository에 의존해 DIP를 위반한다. 이번 작업에서 저장소 계층 전체를 리팩터링하지는 않았다. 새 저장 조정자는 저장 함수와 상태 확인 콜백을 주입받는다.

### 자동 검증과 재현

- 독립 리뷰 2개에서 중복을 제외한 5건과 별도 독립 재리뷰 2개에서 추가 1건을 확인해 수정했다. 수정본의 공유 단위 테스트는 Android host와 iOS Simulator ARM64에서 각각 284개 통과했다. 최신 `an-develop`의 감상 작성 보존 테스트 1개와 기존 266개에 토큰 갱신·로그아웃, 일괄 쓰기와 재조회 경합, 로그인 후 중복 충돌 복구, 상세 조회와 저장 완료 순서를 다루는 회귀 테스트 17개를 추가했다. 이 중 5개는 새 상세 진입의 과거 저장 이벤트 차단, 동일 기록 재저장, 로그인 초기화와 최신 상세 기록·삭제 결과 보존을 검사한다.
- 최종 전체 검증은 통과했다. 직전 실행에서는 기존 `MemberSettingsViewModelTest.partialSuccessIsAppliedAndRetrySendsOnlyIncompleteSetting`이 Main dispatcher 해제 뒤 코루틴 재개로 1회 실패했고, 코드 변경 없는 전체 재실행에서는 재현되지 않았다. 기존 테스트의 종료 처리 안정성은 미해결 제약으로 남긴다.
- Android debug 앱과 계측 테스트 APK 빌드 성공. 새 Compose 계측 테스트 3개는 작성·컴파일했고 기기에서 실행하지 못했다.
- Android CI의 `:app:testDebugUnitTest :app:lintDebug` 작업도 성공했다. 앱 모듈 단위 테스트는 `NO-SOURCE`이며 실제 단위 테스트 수는 위 공유 모듈 결과다. lint 오류 0개, 경고 52개이며 변경한 UI·ViewModel과 새 저장 코드에는 경고가 없었다.
- 아래 iOS XCUITest 실행 기록은 최신 기준 통합 커밋 `6531e0e6` 기준이다. 홈·피드 각각 담기 선택, 로그인 시트 표시, 취소, 원래 위치 복귀와 버튼의 44x44pt 이상 크기를 검사한다. 글자 확대·잘림 감사도 함께 실행한다. 이후 상세 저장 이벤트 재전달 수정은 공유 단위 테스트와 빌드로 검증하며 비회원 홈·피드 시나리오는 재실행하지 않았다.
- 기본 크기: 홈·피드 2개 통과.
- AX5: 홈·피드 2개 통과. 저장 버튼의 터치 영역과 로그인 취소 전후 위치 유지도 통과했다. 홈 전체의 기존 접근성 문제는 아래와 같이 별도 기록한다.
- 전체 터치 영역 감사: 피드는 통과했다. 홈은 기본 크기와 AX5에서 기존 인기 책 캐러셀 표시점으로 실패했다. `HomeScreen.kt`의 해당 표시점은 폭 15/28dp, 높이 32dp로 이번 변경에 포함하지 않았다. AX5 캡처에서는 기존 인기 책 제목·감상 수의 겹침도 확인했다. 새 담기 버튼 크기 검사는 별도로 수행했으며 홈 전체의 HIG 준수 완료로 판단하지 않는다.
- 새 회귀 테스트의 감사에서는 `Hit area is too small`과 `N번째 인기 책 보기` 라벨이 모두 일치하는 기존 표시점 문제만 첨부 파일로 기록하고 제외한다. 나머지 감사 이슈는 테스트 실패로 처리한다.
- 실제 로그인 완료 후 서버에 저장·삭제하는 사용자 흐름, Android 기기 실행, 운영 반영과 실제 사용자 반응은 미검증이다. 저장 성공·실패와 상태 동기화는 모의 서버 및 단위 테스트 결과다.
