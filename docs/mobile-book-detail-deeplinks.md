# 모바일 책 상세 딥링크

2026-11-09 사용자 결정. [이슈 #692](https://github.com/woowacourse-teams/2026-chaekchaek/issues/692)의 구현 기준이다. 플랫폼 실행 결과는 아래에 검증 환경과 범위를 함께 기록한다.

## 목적과 범위

사용자가 앱 밖에서 책을 식별하는 딥링크를 열면 해당 책 상세를 보고, 뒤로가기나 인증 과정에서도 기존 탐색 상태와 입력을 유지한다. Android와 iOS를 함께 대상으로 한다.

이번 작업은 책 상세 외부 진입과 debug 개발자 도구의 딥링크 실행까지 다룬다. Android App Link의 도메인 인증과 알림 발송 기능은 포함하지 않는다. 인증 만료의 공통 요청 재시도와 개발자 도구의 토큰 만료·폐기 기능은 별도 인증 작업에서 다룬다. 서버 변경은 백엔드 담당자와 협의한다.

## 확정한 사용자 동작

| 조건·행동 | 기대 화면·결과 | 보존할 상태 |
| --- | --- | --- |
| 새 실행에서 유효한 책 링크를 연다 | 해당 책 상세를 열고 뒤로가면 홈으로 이동한다 | 외부 진입 목적지 |
| 실행 중이거나 백그라운드인 앱에서 링크를 연다 | 책 상세를 열고 뒤로가면 기존 화면으로 돌아간다 | 기존 화면의 탐색 위치와 입력 |
| 로그인하지 않고 링크를 연다 | 책 상세를 먼저 보여주고 인증이 필요한 행동에서 로그인한다 | 해당 책과 대기 중인 행동 |
| 책장 선택 또는 새 책장 이름 입력 중 다른 책 링크를 연다 | 담기 창을 닫거나 저장을 끝낸 뒤 새 책 상세를 연다 | 기존 담기 대상, 선택과 입력 |
| 현재 보고 있는 책과 같은 링크를 다시 연다 | 현재 상세를 유지한다 | 스크롤과 입력 |
| 링크가 잘못됐거나 책을 찾을 수 없다 | 공통 오류 안내를 표시한다. 닫으면 기존 화면을 유지하고 새 실행이면 홈으로 이동한다 | 기존 화면과 입력 |
| 온보딩 대상자가 링크를 연다 | 기존 온보딩을 먼저 진행하고 온보딩 종료 후 해당 책 상세를 연다 | 온보딩의 선택·입력과 외부 목적지 |

온보딩 대상 판정과 완료·건너뛰기 정책은 [첫 책 선택 온보딩](first-library-onboarding.md)을 따른다. 로그인과 실제 오류 안내는 [모바일 공통 오류 정책](mobile-error-policy.md)을 따르며 로그인 취소를 오류로 표시하지 않는다. 화면과 초안의 저장 수명은 [상태 보존 구현 기록](android-state-preservation-handoff.md)을 따른다.

## 구현 경계

- 외부 URI를 그대로 화면 인자나 API 요청으로 넘기지 않는다. 허용한 scheme, host, 경로와 책 식별자 형식을 검증하고 서버에서 대상 존재 여부를 확인한다. URI의 최종 형식은 구현 시 인텐트 필터·플랫폼 수신 코드·개발자 도구·테스트에 동일하게 적용하고 이 문서에 기록한다.
- Android 최초 Intent와 Activity 재사용 시의 새 Intent, iOS URL 수신을 공통 외부 진입 처리에 연결한다. iOS의 기존 Google 로그인 URL 처리를 유지한다.
- 앱 초기화·인증 복원·온보딩보다 먼저 들어온 목적지는 준비될 때까지 보관하고, 화면 복원이나 재구성으로 이미 처리한 링크를 다시 실행하지 않는다.
- Navigation 3의 실제 백스택으로 위 복귀 정책을 구성한다. Activity task와 앱 내부 백스택을 구분하며 명시적·암시적 진입과 Intent 플래그의 영향을 검증 결과에 남긴다.
- 외부 진입의 책 식별자와 필요한 작은 복원 상태를 저장한다. 인증 토큰·전체 서버 응답·실행 중인 쓰기 콜백은 Saved State에 넣지 않는다.
- debug 개발자 도구에서 실제 외부 진입 경로로 링크를 실행한다. 앱 내부에서 목적지를 직접 여는 것만으로 외부 진입 검증을 대신하지 않는다. 사용자용 오류·로그인 UI는 기존 공통 컴포넌트를 재사용한다. 2026-11-09 사용자 결정에 따라 개발자 도구 UI는 [로컬 Figma와 HTML 승인 절차](local-figma-html-workflow.md)로 진행한다.
- `AppNavigation`에 의존 객체 생성·인증 동기화·목적지 이동이 집중된 단일 책임 원칙 위반이 있다. 새 URI 해석 책임까지 추가하지 않고 이번 흐름에 필요한 범위만 분리한다.

### 2026-11-12 최종 검증

모든 실행은 로컬 합성 API(`android/scripts/book-deeplink-fixture.py`)를 사용했다. 개발·운영 서버의 실제 도서 응답으로는 실행하지 않았다.

- iOS 5건: 콜드 진입 후 홈 복귀, 실행 중·백그라운드 진입 후 발견 탭 검색어 보존, 온보딩 종료 후 목적지 재개, 개발자 도구 링크 실행과 입력 보존, 404·503 공통 오류 안내와 복귀.
- Android 9건: 콜드·실행 중·백그라운드 진입과 검색어 보존, 동일 도서 재진입 상태 보존, 상세가 링크 조회 응답을 재사용, 조회 중 Activity 재생성 후 재개, 소비한 Intent의 재생성 재실행 방지, 직접 진입 후 홈 복귀와 재생성, 404·503 안내와 복귀, 온보딩 건너뛰기 후 재개, 개발자 도구 실행.
- Android 계측 APK는 `an-develop`의 기존 계측 테스트가 #704 모델 변경으로 컴파일되지 않아, [PR #724](https://github.com/woowacourse-teams/2026-chaekchaek/pull/724)의 수정 `141065d8`을 임시 체크아웃에만 얹어 빌드했다. 이 PR에는 그 수정이 포함되지 않는다.
- 같은 링크의 조회는 화면 효과가 다시 시작돼도 1회만 보낸다. 수정 전에는 iOS 콜드 진입 3회 중 1회에서 75ms 간격의 중복 조회가 재현됐고, 수정 후 3회 반복에서 재현되지 않았다.
- `simctl openurl`로 실행 중인 앱에 링크를 보내면 iOS가 "'책췍'에서 열겠습니까?" 확인창을 띄울 때가 있다. 앱이 아닌 시스템 화면이므로 UI 테스트가 나타날 때만 `열기`를 누른다.
- 미검증: 딥링크로 진입한 뒤 실제 공급업체 로그인을 거쳐 대기 작업을 재개하는 흐름, iOS 시스템 프로세스 종료 후 복원(저장 경로 미구현), 실제 기기.

HTML v1은 데스크톱 너비 1120, 모바일 너비 390·320에서 브라우저로 확인했다. Gowun Dodum·Pretendard 로딩, 가로 넘침 없음, 정상 URI 형식 확인, 잘못된 링크·책 없음·연결 오류 안내, 오류 닫기 후 입력 보존, 재시도 버튼과 조회 중 상태를 확인했다. HTML의 동작은 시뮬레이션이며 실제 앱·서버 동작의 검증 결과가 아니다. 로컬 원본의 파일 해시·내보낸 시각·사용한 노드와 승인 절차는 [로컬 디자인 기록](local-figma-html-workflow.md)에 둔다.

## 검증 계획

아래 항목을 Android와 iOS에서 각각 확인한다. iOS는 시스템이 프로세스를 종료한 뒤 이전 딥링크나 백스택을 복원하는 앱 저장 경로가 없다. 최종 결과에는 정확한 SHA, 빌드 환경과 기기를 기록하고 빌드·단위 테스트·실제 사용 흐름의 결과를 구분한다.

| 시나리오 | 확인할 결과 |
| --- | --- |
| 앱 종료·백그라운드·실행 중 진입 | 대상 책과 상태별 뒤로가기 정책이 일치한다 |
| 비로그인 진입 후 인증이 필요한 행동 | 상세 열람이 가능하고 로그인 후 같은 화면·작업으로 복귀한다 |
| 책장 선택 또는 책장 생성 중 새 딥링크 | 창을 닫거나 저장을 마친 뒤 링크가 열리고 기존 담기 대상이 바뀌지 않는다 |
| 현재 상세와 같은 책의 링크 재수신 | 새 entry를 중복으로 쌓지 않고 스크롤·초안을 유지한다 |
| 잘못된 scheme·host·경로·식별자 | 잘못된 요청을 보내지 않고 정한 오류·복귀 정책을 따른다 |
| 서버에서 책을 찾을 수 없음 | 빈 화면 없이 오류를 안내하고 기존 상태 또는 홈으로 복귀한다 |
| 온보딩 대상자의 외부 진입 | 온보딩 종료 전 목적지를 잃지 않고 종료 후 해당 상세를 연다 |
| 외부 진입 후 구성 변경·시스템 프로세스 복원 | 목적지와 기존 복귀 상태를 복원하고 링크를 중복 실행하지 않는다 |
| debug 도구에서 링크 실행 | 실제 플랫폼 URL 진입 경로를 거쳐 동일한 결과가 나온다 |
