# 모바일 공통 오류 안내 정책

- 결정일과 Figma 확인일: 2026-10-20
- 배치 수정과 재확인일: 2026-10-21
- 적용 범위: 온보딩과 로그인, 홈, 피드, 발견, 내 서재, 책 상세 및 입력 시트의 Android와 iOS 오류 안내
- 현재 상태: 정책과 Figma를 기준으로 Android와 iOS 공통 코드 적용. 플랫폼별 검증 범위는 아래 앱 적용 기록에서 구분한다.

## 같은 UI를 사용하는 기준

실제 오류는 모두 `책췍/ErrorDialog`로 표시한다. 제목, 설명과 가능한 행동만 오류의 의미에 맞게 바꾼다. 화면에서 스낵바, 인라인 안내나 전용 실패 화면을 선택하지 않는다. 오류 분류, 문구와 복구 행동의 결정은 공통 정책이 담당하고, 각 화면은 보존할 상태와 실행할 작업을 연결한다.

| 상황 | 공통 다이얼로그 | 닫은 뒤 또는 재시도할 때 |
| --- | --- | --- |
| 입력값 검증 실패 | Confirm: `확인` | 저장 또는 제출 시 안내한다. 입력을 지우지 않고 수정할 수 있게 한다. 매 글자 입력마다 다이얼로그를 띄우지 않는다. |
| 네트워크, 서버, 조회, 저장 실패 중 재시도 가능 | Retry: `다시 시도`, `닫기` | 해당 작업을 다시 실행한다. 화면, 입력, 검색어, 제출 검색어, 정렬, 필터, 선택과 기존 내용을 유지한다. |
| 복구 행동이나 재시도가 없는 오류 | Confirm: `확인` | 사실에 맞는 설명을 표시하고 현재 상태를 유지한다. 의미 없는 재시도를 제공하지 않는다. |
| 인증 만료 | Login: `로그인`, `닫기` | 로그인 성공 후 대기 중인 작업을 이어간다. 닫기만으로 작업을 실행하거나 다른 화면으로 이동하지 않는다. |
| 공급업체 또는 서버 로그인 실패 | Retry: `다시 시도`, `닫기` | 로그인 창 위에 표시한다. 오류만 닫으면 로그인 창과 선택한 책을 유지한다. 온보딩도 같은 방식이다. |
| 사용자의 로그인 취소 | 오류 안내 없음 | 실패로 처리하지 않는다. 기존 화면과 선택을 유지한다. |
| 온보딩 저장 중 일부 도서만 실패 | Retry: `다시 시도`, `닫기` | 선택과 완료된 저장 결과를 유지한다. 저장하지 못한 책만 다시 저장하며, 해당 API의 409는 성공으로 처리한다. |
| 새로고침 또는 추가 조회 실패 | Retry: `다시 시도`, `닫기` | 기존 목록과 조건, 스크롤 및 유효한 커서를 유지한다. 실패를 데이터 끝이나 결과 없음으로 바꾸지 않는다. |

오류 다이얼로그의 X, 확인과 닫기는 오류 안내를 닫는 행동이다. 바탕에 있는 입력 시트나 로그인 창까지 닫지 않는다. 별도의 건너뛰기나 화면 닫기는 기존 흐름을 따른다. 온보딩 건너뛰기는 이미 저장된 책을 삭제하지 않는다.

저장과 제출 시 안내한다는 기준은 오류 메시지의 노출 시점이다. `android/AGENTS.md`에 명시된 입력, 붙여넣기, 초기값과 복원값의 공통 크기 제한은 그대로 적용하며 제출 시 검사만으로 대체하지 않는다.

성공 안내, 실제 검색 결과 없음, 비로그인 사용자의 최초 로그인 유도와 파괴적 작업의 사전 확인은 오류가 아니다. 이 정책만으로 해당 UI를 오류 다이얼로그로 바꾸지 않는다. 공급업체 네이티브 로그인 버튼의 규격도 유지한다.

## 적용과 검증 경계

- 2026-10-21 상단 여백 보정: 상단 패딩은 8, X 행과 본문 사이 간격은 0이다. X의 44 x 44 터치 영역을 유지하며 제목 시작 위치를 84에서 52로 줄였다. 본문 안의 제목, 설명과 버튼 사이 간격은 기존 16을 유지한다.
- X 터치 영역의 오른쪽 여백은 8로 줄인다. 제목, 설명과 하단 버튼의 좌우 내부 여백은 24로 유지한다.

- Figma MCP로 메인 컴포넌트와 인스턴스 연결, 다이얼로그 경계와 텍스트 넘침을 확인했다. 390과 320 너비 캡처에서 문구, 버튼, 로그인 창 보존 및 목록 위 표시를 확인했다.
- 파일 안의 컴포넌트 등록을 완료했으며 팀 라이브러리 게시는 수행하지 않았다. 캡처는 앱 실행이나 프로토타입 동작의 증거가 아니다.
- 앱의 화면별 오류 스낵바, 인라인 오류와 전용 실패 화면을 공통 오류 다이얼로그로 전환했다. 내부 상태의 기존 오류 필드는 일부 유지하지만 화면에서 별도 오류 UI로 표시하지 않는다.
- 적용 시 Android와 iOS에서 입력 검증, 로그인 실패와 취소, 인증 만료 후 이어가기, 조회 실패와 재시도, 온보딩 부분 저장을 같은 시나리오로 검증한다. 빌드와 공통 테스트 결과만으로 양 플랫폼의 사용자 흐름 검증을 대체하지 않는다.

이 문서와 현재 사용자 결정은 과거 온보딩 전용 실패 화면, 갱신 오류 스낵바와 추가 조회 하단 오류 안내보다 우선한다. 이전 문서의 검증 기록은 해당 당시 구현의 근거로만 읽는다.

### 코드 적용

- `ErrorRecoveryState`가 오류 분류, 사용자용 문구와 일회성 복구 작업을 담당한다. 화면마다 오류 정책까지 결정하던 책임을 분리해 단일 책임 원칙에 맞춘다. 화면과 ViewModel은 보존할 상태와 실제 재실행 작업만 연결한다.
- `ErrorRecoveryHost`가 로그인 시트를 포함한 현재 UI 위에 오류 하나를 표시한다. 이전 오류의 지연 응답으로 새 오류를 닫거나 작업을 중복 실행하지 않는다. Confirm은 복구 작업을 실행하지 않는다.
- `ChaekErrorDialog`는 공유 Compose UI이므로 Android와 iOS가 같은 배치, 글꼴, 문구와 행동을 사용한다. 상단 8, 별도 X 행 44, X 오른쪽 8, 본문 좌우 24, 두 버튼 가로 배치를 적용한다. 긴 내용은 세로로 스크롤하며 두 버튼의 높이를 맞춘다.
- 온보딩, 로그인, 홈, 피드, 발견, 서재, 설정, 책 상세와 입력 시트의 실제 오류를 같은 정책에 연결한다. 성공 안내, 실제 빈 결과, 비회원 로그인 유도와 삭제 사전 확인은 기존 의미를 유지한다.
- 401은 로그인 후 새 토큰으로 원래 작업을 재개한다. 조회와 쓰기 재시도를 구분하고 실패한 쓰기 자체를 다시 실행한다. 온보딩은 완료한 ISBN을 제외하며 409를 완료로 간주한다.
- 감상, 댓글, 쪽수와 닉네임 입력창은 저장 성공 후 닫는다. 실패나 오류창 닫기로 입력과 선택을 지우지 않는다. 서재 다중 선택도 쓰기 성공 후 해제한다. 검색 실패 후 이전 결과의 커서를 새 검색어에 사용하지 않는다.
- Android Credential Manager 취소와 iOS Google 및 Apple 로그인 취소를 명시적으로 구분한다. 공급업체 실패는 공통 Retry를 표시하고, 취소는 오류를 표시하지 않는다.

Android UI 테스트는 실제 공유 화면과 상태 fixture를 사용한다. iOS 감상 테스트는 `android/scripts/review-draft-qa-server.py`의 로컬 HTTP 실패 후 성공 응답을 사용하며, 로그인 실패와 취소는 DEBUG 전용 공급업체 callback fixture를 사용한다. 운영 계정이나 운영 데이터에 쓰지 않는다.

실제 Google 및 Apple 계정 인증, 운영 API, 온보딩 전체의 재로그인과 부분 저장, 모든 화면과 기기 크기의 실행은 미검증이다. 온보딩 복구와 부분 저장은 공통 ViewModel 테스트로 검증했으며 양 플랫폼 전체 실행을 대신하지 않는다. 접근성 감사 통과는 오류창 바깥의 모든 화면이 HIG를 충족한다는 뜻이 아니다.

이 세션의 재현 로그와 캡처는 `/tmp/chaekchaek-566-*`에 저장했다. iOS 결과 번들은 `ios-large-final.xcresult`와 `ios-ax5.xcresult` 접미사를 사용한다. 임시 파일은 장기 보관 자료가 아니며 재검증할 때 위 테스트를 실행한다. 검증에 사용한 iOS 크기는 large로 복원하고 이 작업이 부팅한 시뮬레이터만 종료했다. Android 전용 에뮬레이터도 종료하고 임대를 해제했다.
