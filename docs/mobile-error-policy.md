# 모바일 공통 오류 안내 정책

- 결정일과 Figma 확인일: 2026-10-20
- 배치 수정과 재확인일: 2026-10-21
- 적용 범위: 온보딩과 로그인, 홈, 피드, 발견, 내 서재, 책 상세 및 입력 시트의 Android와 iOS 오류 안내
- 현재 상태: 정책 확정과 Figma 수정 완료. 이 변경에서 앱 코드는 수정하지 않았으며, 앱 적용과 양 플랫폼 실행 검증은 미완료다.

## 같은 UI를 사용하는 기준

실제 오류는 모두 `책췍/ErrorDialog`로 표시한다. 제목, 설명과 가능한 행동만 오류의 의미에 맞게 바꾼다. 화면에서 스낵바, 인라인 안내나 전용 실패 화면을 선택하지 않는다. 오류 분류, 문구와 복구 행동의 결정은 공통 정책이 담당하고, 각 화면은 보존할 상태와 실행할 작업을 연결한다.

| 상황 | 공통 다이얼로그 | 닫은 뒤 또는 재시도할 때 |
| --- | --- | --- |
| 입력값 검증 실패 | Confirm: `확인` | 저장 또는 제출 시 안내한다. 입력을 지우지 않고 수정할 수 있게 한다. 매 글자 입력마다 다이얼로그를 띄우지 않는다. |
| 네트워크, 서버, 조회, 저장 실패 중 재시도 가능 | Retry: `다시 시도`, `닫기` | 해당 작업을 다시 실행한다. 화면, 입력, 검색어, 제출 검색어, 정렬, 필터, 선택과 기존 내용을 유지한다. |
| 복구 행동이나 재시도가 없는 오류 | Confirm: `확인` | 사실에 맞는 설명을 표시하고 현재 상태를 유지한다. 의미 없는 재시도를 제공하지 않는다. |
| 인증 만료 | Login: `로그인`, `닫기` | 로그인 성공 후 대기 중인 작업을 이어간다. 닫기만으로 작업을 실행하거나 다른 화면으로 이동하지 않는다. |
| 공급업체 또는 서버 로그인 실패 | Retry: `다시 시도`, `닫기` | 로그인 창 위에 표시한다. 오류만 닫으면 로그인 창과 선택한 책을 유지한다. 온보딩도 같은 방식이다. |
| 사용자의 로그인 취소 | 오류 안내 없음 | 실패로 처리하지 않는다. 기존 화면과 선택을 유지한다. |
| 온보딩 저장 중 일부 도서만 실패 | Retry: `다시 시도`, `닫기` | 선택과 완료된 저장 결과를 유지한다. 저장하지 못한 책만 다시 저장하며, 해당 API의 409는 성공으로 처리한다. |
| 새로고침 또는 추가 조회 실패 | Retry: `다시 시도`, `닫기` | 기존 목록과 조건, 스크롤 및 유효한 커서를 유지한다. 실패를 데이터 끝이나 결과 없음으로 바꾸지 않는다. |

오류 다이얼로그의 X, 확인과 닫기는 오류 안내를 닫는 행동이다. 바탕에 있는 입력 시트나 로그인 창까지 닫지 않는다. 별도의 건너뛰기나 화면 닫기는 기존 흐름을 따른다. 온보딩 건너뛰기는 이미 저장된 책을 삭제하지 않는다.

저장과 제출 시 안내한다는 기준은 오류 메시지의 노출 시점이다. `android/AGENTS.md`에 명시된 입력, 붙여넣기, 초기값과 복원값의 공통 크기 제한은 그대로 적용하며 제출 시 검사만으로 대체하지 않는다.

성공 안내, 실제 검색 결과 없음, 비로그인 사용자의 최초 로그인 유도와 파괴적 작업의 사전 확인은 오류가 아니다. 이 정책만으로 해당 UI를 오류 다이얼로그로 바꾸지 않는다. 공급업체 네이티브 로그인 버튼의 규격도 유지한다.

기존 화면의 노드 ID를 유지하고 이전 오류 표시를 숨긴 뒤 공통 컴포넌트 인스턴스를 연결했다. 기존 하단 오류 컴포넌트의 Error 상태는 과거 표현으로 표시했으며 새 구현에서는 사용하지 않는다. 새로고침 보드와 디자인 시스템 섹션의 기존 겹침을 해소하기 위해 새로고침 섹션의 위치를 이동했다.

Gowun Dodum 일반 텍스트, 기존 Pretendard 닫기 아이콘, 디자인 시스템 변수와 버튼을 재사용했다. 390 너비의 다이얼로그는 358, 320 너비에서는 288이며 좌우 여백은 16이다. 긴 문구는 줄바꿈한다. 두 버튼은 같은 행에 가로로 배치하며, 왼쪽은 `닫기`, 오른쪽은 `다시 시도` 또는 `로그인`이다. Confirm은 `확인` 버튼 하나를 사용한다. X 버튼은 제목과 같은 행에 두지 않고 제목 위의 별도 행 우측 상단에 배치한다. 320 너비에서도 두 버튼을 세로로 바꾸지 않는다.

## 적용과 검증 경계

- Figma MCP로 메인 컴포넌트와 인스턴스 연결, 다이얼로그 경계와 텍스트 넘침을 확인했다. 390과 320 너비 캡처에서 문구, 버튼, 로그인 창 보존 및 목록 위 표시를 확인했다.
- 파일 안의 컴포넌트 등록을 완료했으며 팀 라이브러리 게시는 수행하지 않았다. 캡처는 앱 실행이나 프로토타입 동작의 증거가 아니다.
- 실제 앱에는 화면별 스낵바, 인라인 오류와 온보딩 실패 상태가 남아 있다. 공통 오류 분류와 UI 적용, 플랫폼별 로그인 취소 구분 및 대기 작업 복구는 코드 변경과 검증이 필요하다.
- 적용 시 Android와 iOS에서 입력 검증, 로그인 실패와 취소, 인증 만료 후 이어가기, 조회 실패와 재시도, 온보딩 부분 저장을 같은 시나리오로 검증한다. 빌드와 공통 테스트 결과만으로 양 플랫폼의 사용자 흐름 검증을 대체하지 않는다.

이 문서와 현재 사용자 결정은 과거 온보딩 전용 실패 화면, 갱신 오류 스낵바와 추가 조회 하단 오류 안내보다 우선한다. 이전 문서의 검증 기록은 해당 당시 구현의 근거로만 읽는다.
