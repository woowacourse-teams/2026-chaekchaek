# 화면 기획서 템플릿 규칙

## 기준 노드

- 파일: `designs.pen`
- 원본 템플릿: `MvCYw` (`책 상세 화면 상세 기획서 · 표 형식`)
- 시트 예시: `VprFZ`, `YYbQc`
- 원본은 보존하고 새 기획서는 복제본에서 작성한다.

## 한 시트의 구조

각 시트는 아래 순서를 유지한다.

1. 제목 행: `N-N. 화면명 상세 기획서`
2. 제목 밑줄
3. 메타 정보: `Screen ID`, `Screen Path`
4. 본문 왼쪽: 휴대폰 한 화면과 마커
5. 본문 오른쪽: `Information`, `Control` 표

본문의 화면 영역과 표 영역 사이 간격은 32px로 유지한다.

## 화면 영역

- 화면 영역 너비: 430px
- 화면 영역 안쪽 여백: 20px
- 휴대폰 뷰포트: 390x844px
- 뷰포트는 `clip: true`로 설정한다.
- 휴대폰 화면을 세로로 늘리지 않는다.
- 긴 화면은 스크롤 위치별로 시트를 복제하고 내부 화면의 y 위치만 바꿔 보여준다.
- 모달, 바텀 시트, 입력 상태처럼 화면 상태가 크게 달라지면 별도 시트를 만든다.
- 스티키 요소는 스크롤 화면 내부가 아니라 390x844 뷰포트의 직접 자식 오버레이로 둔다.
- 하단 스티키 요소는 특별한 요구가 없으면 좌우 16px, 하단 16px 여백을 사용한다.

화면 위에는 마커와 필요한 행동 화살표만 추가한다. 데이터 이름이나 긴 설명을 화면에 직접 쓰거나 별도의 색상 버튼과 카드로 만들지 않는다.

## Information 표

컴포넌트에 표시되는 데이터를 기록한다.

| 열 | 너비 | 작성 내용 |
| --- | ---: | --- |
| No | 58px | `I1`, `I2`처럼 시트 전체에서 고유한 정보 번호 |
| 표시 정보 | 220px | 사용자가 보는 정보 묶음 또는 컴포넌트 이름 |
| 데이터 | 360px | 실제 출력 필드 또는 업무 데이터 이름 |
| 표시 조건 | 나머지 | 항상 표시, 값 없음, 로그인 여부, 로딩과 오류 등 |

- 헤더 높이: 38px
- 행 높이: 내용에 따라 70px 이상
- 셀 안쪽 여백: 세로 8px, 가로 10px
- `데이터`에는 `장르`, `출판 시기`, `쪽수`, `평균 별점`, `평가 수`처럼 실제 값의 의미를 적는다.
- 정확한 API 필드명을 알고 있으면 `genre`, `publishedAt`, `pageCount`처럼 함께 적는다.
- 필드명을 확인하지 못했으면 임의로 만들지 말고 업무 데이터 이름 뒤에 `필드 확인 필요`를 표시한다.
- 값이 없거나 일부 데이터가 숨겨질 때의 대체 표시도 `표시 조건`에 적는다.

정보 마커는 다음 형식을 사용한다.

- 크기: 28x28px
- 번호: `I1`, `I2`, `I3` 순서
- 채움: 검정 계열, 현재 템플릿은 `$cc-ink`
- 테두리: 흰색 2px, 현재 템플릿은 `$cc-surface`
- 모서리 반경: 2px

## Control 표

사용자가 수행하는 행동과 그 결과를 기록한다.

| 열 | 너비 | 작성 내용 |
| --- | ---: | --- |
| No | 52px | `1`, `2`처럼 시트 전체에서 고유한 기능 번호 |
| 기능 | 200px | 저장, 별점 주기, 필터 전환처럼 기능 이름 |
| Type | 82px | `Tap`, `Input`, `Swipe`, `Long press` 등 입력 방식 |
| 처리 결과 | 330px | 상태 변경, 이동, 저장, 갱신, 오류 처리 결과 |
| 실행 조건 | 나머지 | 로그인, 권한, 데이터 상태, 실패 시 유지 조건 등 |

- 헤더 높이: 38px
- 기본 행 높이: 76px
- 셀 안쪽 여백: 세로 8px, 가로 10px
- `기능`에는 사용자가 무엇을 조작하는지 적는다.
- `Type`에는 클릭, 필터 선택, 입력, 세로 또는 가로 스와이프처럼 실제 제스처를 적는다.
- `처리 결과`에는 행동 뒤 무엇이 바뀌는지 반드시 적는다. 단순히 `버튼 클릭`으로 끝내지 않는다.
- `실행 조건`에는 로그인 필요, 입력 범위, 실패 시 기존 상태 유지 같은 제약을 적는다.

기능 마커는 다음 형식을 사용한다.

- 크기: 28x28px
- 번호: `1`, `2`, `3` 순서
- 채움: 필요한 포인트 색상 하나, 현재 템플릿은 `$cc-accent`
- 테두리: 흰색 2px, 현재 템플릿은 `$cc-surface`
- 모서리 반경: 14px

행동 방향이나 이동 경로가 중요할 때만 기능 마커에 포인트 색상 화살표를 연결한다. 화살표 옆에는 `탭`, `필터 선택`, `세로 스와이프`처럼 행동을 짧게 적는다.

## 문서 스타일

- 문서 배경과 표 셀은 흰색을 기본으로 한다.
- 제목, 표 헤더, 정보 마커는 검정 계열을 사용한다.
- 구분선과 보조 문구는 회색 계열을 사용한다.
- 포인트 색상은 기능 마커, 행동 화살표, 꼭 필요한 강조 셀에만 사용한다.
- 화면 기획서 문서 외형에 첵췍 앱의 장식적 색상과 컴포넌트 스타일을 강제하지 않는다.
- 휴대폰 화면 복제본에는 실제 제품 디자인을 그대로 유지한다.

## 작성 점검표

- 제목, Screen ID, Screen Path가 대상 화면과 일치하는가
- 휴대폰 화면이 390x844px 안에서 잘리는가
- 긴 화면 대신 필요한 상태별 시트가 분리됐는가
- 정보 마커와 `Information` 행이 모두 대응하는가
- 기능 마커와 `Control` 행이 모두 대응하는가
- 모든 데이터가 구체적인 값 또는 필드 수준으로 적혔는가
- 모든 행동에 입력 방식, 처리 결과, 실행 조건이 적혔는가
- 스티키 요소가 뷰포트의 직접 자식인가
- 마커의 흰색 테두리가 유지되는가
- 화면과 표에 겹침, 잘림, 빈 행이 없는가
