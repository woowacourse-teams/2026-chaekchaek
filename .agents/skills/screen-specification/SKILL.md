# 화면 기획서

`designs.pen`의 `MvCYw`를 화면 기획서 원본 템플릿으로 사용한다. 사용자가 원본 갱신을 명시하지 않으면 `MvCYw`를 직접 수정하지 말고 복제본에서 작업한다.

Pencil 편집 안전 절차는 같은 프로젝트의 `chaekchaek-design-system` 스킬을 따른다. 문서 외형에는 앱 디자인 시스템을 강제하지 않는다. 화면 캡처 자체에는 기존 앱 컴포넌트와 토큰을 유지하고, 문서 영역은 흰색, 검정, 회색 중심으로 구성한다.

정확한 포맷과 작성 규칙은 [references/template.md](references/template.md)를 전부 읽고 적용한다.

## 요청 모드

### 화면 기획서 작성

1. 대상 화면 Node ID와 필요한 상태 또는 행동 범위를 확인한다.
2. `MvCYw`와 대상 화면을 Pencil로 검사하고 각각 스크린샷을 남긴다.
3. `MvCYw` 또는 필요한 시트를 복제해 빈 캔버스 공간에 배치한다.
4. 제목, Screen ID, Screen Path를 대상 화면에 맞게 바꾼다.
5. 실제 컴포넌트 경계를 확인한 뒤 정보 마커와 기능 마커를 해당 컴포넌트 가장자리에 배치하고 오른쪽 표의 No와 일치시킨다. 상태 화면을 복제했다면 화면에 보이지 않는 이전 상태의 표 행과 마커를 그대로 두지 않는다.
6. `Information`에는 현재 코드 또는 `openapi3.yaml`에서 확인한 실제 출력 필드를, `Control`에는 사용자 행동과 처리 결과를 기록한다. 화면, 모달, 바텀 시트, 다이얼로그를 열거나 닫거나 이동하면 대상 UI와 도착 화면 또는 복귀 상태까지 처리 결과에 명시한다.
7. 스크롤 위치나 상태가 달라지면 긴 휴대폰 화면을 만들지 말고 같은 형식의 시트를 추가한다.
8. 같은 화면의 시트는 아래에 쌓지 않고 오른쪽으로 배열하며, 관련 화면, 모달, 다이얼로그 사이에는 행동 또는 상태 조건을 적은 화살표를 둔다.
9. 완성된 각 시트를 스크린샷으로 검증한다.

### 화면 기획서 템플릿

- 기본 응답은 기준 노드 `MvCYw`와 포맷 규칙을 안내한다.
- 캔버스에 템플릿 배치를 요청하면 `MvCYw`를 복제하고 화면별 내용만 비운 복제본을 만든다.
- 원본 `MvCYw`의 수정은 사용자가 템플릿 자체의 변경을 명시한 경우에만 수행한다.

## 완료 조건

- 모든 마커의 No가 표의 No와 정확히 대응한다.
- 모든 마커가 설명 대상 컴포넌트의 실제 위치와 맞닿아 있다.
- 모든 화면 컴포넌트의 주요 출력 데이터가 `Information`에 빠짐없이 기록된다.
- `Information`의 필드가 현재 코드 또는 `openapi3.yaml`에서 확인됐으며 로컬 UI 상태는 별도로 표시된다.
- 모든 요청 행동의 입력, 결과, 실행 조건이 `Control`에 기록된다.
- 화면, 모달, 바텀 시트, 다이얼로그의 열기, 닫기, 이동 결과에 대상 UI와 도착 화면 또는 복귀 상태가 명시된다.
- 같은 화면의 상태가 가로로 이어지고 관련 상태 사이의 화살표에 전환 원인이 적혀 있다.
- 휴대폰 뷰포트는 한 화면 크기를 넘지 않는다.
- 스티키 요소와 스크롤 콘텐츠의 계층이 분리되어 있다.
- 잘림, 겹침, 빈 표 행, 임시 문구가 없다.
