## Code Review Rules

- 코드 리뷰 결과는 한국어로 작성한다.
- 기능상의 오류뿐 아니라 정상적으로 동작하는 코드의 품질과 설계의 적절성도 검토한다.
- 변경 목적과 설계 의도를 파악하고, 변경된 코드뿐 아니라 관련 호출부와 의존 관계도 함께 검토한다.
- 가독성, 네이밍, 책임 분리, 응집도와 결합도, 추상화, 유지보수성 관점에서 개선점을 제안한다.
- 개선이 필요한 이유를 현재 코드의 구체적인 맥락에서 설명한다.
- 현재 설계와 대안의 장단점 및 트레이드오프를 비교한다.
- 설계 원칙이나 패턴의 적용 자체를 목적으로 개선을 제안하지 않는다.
- 적절한 설계 결정과 의미 있는 개선 사항도 평가한다.
- 실제 결함과 설계 개선 제안을 구분한다.
