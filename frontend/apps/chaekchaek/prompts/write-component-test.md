# 테스트 코드 작성 

## 작업 대상

- 페이지 컴포넌트: frontend/apps/chaekchaek/src/pages/{}/{}.test.tsx
- 테스트 케이스: `it("")`
- 지정한 테스트 케이스를 구현한다.

## 테스트 환경
- 테스트 러너: Vitest
- 컴포넌트 테스트: React Testing Library
- API Mock: MSW
- 테스트 데이터: 별도의 Fixture 파일

## 작업 원칙

### 테스트 설계

- 사용자 관점에서 컴포넌트의 동작과 렌더링 결과를 검증한다.
- 요청하지 않은 테스트 시나리오를 임의로 추가하지 않는다.
- 테스트 통과를 목적으로 검증 조건을 삭제하거나 완화하지 않는다.
- 요청한 시나리오와 실제 동작이 일치하지 않으면 임의로 기대 결과를 변경하지 않고 문제를 보고한다.

### Mock 및 Fixture

- API 요청은 MSW를 사용하여 Mock 처리한다.
- 테스트 응답 데이터는 별도의 Fixture 파일에서 관리한다.
- 테스트 간 상태가 공유되지 않도록 관리한다. (MSW 핸들러 초기화 등)

### 작업 범위

- 테스트 작성을 위해 프로덕션 코드를 수정하지 않는다.
- 테스트 실패 여부와 관계없이 프로덕션 코드를 수정하지 않는다.

### 작업 완료

- 작성한 테스트를 실행하고 결과를 확인한다.
- 테스트 코드 자체의 오류는 수정하되, 기대 동작을 만족하지 않아 발생한 테스트 실패는 수정하지 않고 보고한다.
- 대상 테스트 파일의 전체 테스트를 실행한다.
- 테스트 결과는 다음과 같이 구분하여 보고한다.
  - 요청한 테스트: 통과 여부 및 실패한 경우 오류 내용
  - 기존 테스트: 통과 여부 및 실패한 테스트 목록과 오류 내용
- 이번 작업에서 발생한 변경 사항만 Git Commit 한다.
- 기존 변경 사항이 섞여 있다면 hunk 단위로 분리하여 스테이징한다.
- 이번 작업에서 변경한 코드만 선택적으로 스테이징한다. (`git add -p` 등 활용)
- 다른 작업의 변경 사항은 커밋에 포함하지 않는다.
- 커밋 메시지는 다음 형식을 따른다.
  `[FE] test(테스트하는 컴포넌트이름): 테스트 설명`
