# Code Quality Review
## 기본 지침
  - 코드 리뷰는 한국어로 작성한다  
  - 기능 오류와 함께 코드 품질 측면에서 코드 리뷰를 한다
  - 코드를 직접 수정하지 않는다
## 코드 품질 평가 기준
  - 가독성, 네이밍, layered 경계(계층 간 책임과 의존 관계), 타입 준수, 타입 구조 및 모델링의 적절성, 응집도와 결합도, 도메인 분리, 유지보수를 고려한 확장성 측면에서의 코드 퀄리티에 대해서 리뷰한다
  - 코드 품질에 관한 일반적인 원칙을 기계적으로 적용하지 않는다
  - 현재 코드의 맥락에서 해당 코드가 왜 문제가 되는지 어떤 영향을 줄 수 있는지 구체적인 근거와 함께 설명한다
  - 코드의 복잡성과 개선에 따른 비용도 함께 고려한다
  - 개별 코드의 적절성뿐만 아니라 변경사항 전반에서 선택한 설계 및 구현 접근 방식의 적절성도 평가한다
## 리뷰 범위
  - 리뷰의 중심 대상은 git commit 에 포함된 변경사항이다
  - 변경사항의 적절성과 영향을 판단하기 위해 관련된 정의부, 호출부와 의존 관계를 함께 확인한다
  - 현재 변경사항과 무관한 기존 코드의 문제는 원칙적으로 리뷰 대상에서 제외한다
## 리뷰 작성 원칙
  - 사고 유도: 문제와 판단 근거를 명확히 전달하되 개선 방법을 스스로 고민할 수 있게 유도한다
  - 필요한 경우 관련된 개념이나 키워드를 제시한다
  - 개선 방법 제시: 여러 개선 방법이 존재하는 경우 각 방법의 특성과 트레이드오프를 설명하여 개발자가 최종 변경 방식을 결정할 수 있도록 리뷰 한다
## 리뷰 기록 방식
  - 특정 코드 라인에 대한 리뷰와 변경 사항 전반에 대한 설계 및 구현 접근 방식에 대한 리뷰를 구분한다
  - 특정 코드 라인에 대한 리뷰는 관련 코드라인에 inline comment로 남긴다
  - 특정 코드에 국한되지 않는 전반적인 설계 및 구현 접근 방식에 대한 리뷰의 경우 별도로 작성한다
## 테스트 코드에 대한 리뷰
  - 구체적인 테스트 구현 방식보다 테스트의 설계와 구성에 중점을 두고 리뷰한다
  - 명확성: 검증하려는 동작이나 요구사항이 테스트 설명에 구체적으로 드러나는가
  - 필요성: 검증할 가치가 있는 동작이나 요구사항인지
  - 배치의 적절성: 이 테스트가 이 파일, 이 코드 위치에 있는 것이 적절한지에 대해서 평가한다
## 프로세스
  - push 이전의 원격 브랜치 커밋을 확인한다
  - 현재 브랜치의 commit 을 push 한다
  - push 이전과 이후의 commit 사이의 변경사항을 리뷰 대상으로 삼는다
  - 여러 commit이 포함된 경우 개별적으로 리뷰하지 않고 누적된 변경사항을 기준으로 리뷰한다
  - 리뷰 결과를 GitHub에 기록한다
## 리뷰 시 유의 사항
  - 리뷰를 남기기 위해 불필요한 개선점을 만들어내지 않는다.
  - 실제 기능 오류, 코드 품질 문제, 설계상의 개선 제안, 개인적인 선호를 구분하여 전달한다.
  - 현재 구현이 합리적인 경우 변경을 강요하지 않는다.
