# 백엔드 코드 리뷰 지침

이 문서는 로컬 리뷰와 GitHub PR 리뷰의 검토 기준과 보고 방식을 정의한다. 코드 규칙은 [개발 지침](development-guide.md)을 기준으로 하며, 해당 문서의 우선 적용 규칙과 예외를 함께 적용한다.

## 검토 기준

- 변경으로 새로 생기거나 악화된 문제를 중심으로 검토한다. 판단에 필요한 호출부, 관련 도메인, 테스트까지 확인하되, 변경과 무관한 기존 코드의 정리를 요구하지 않는다.
- 동작 오류, 접근 권한, 데이터 무결성, API 호환성을 우선 검토한다. 발생 조건, 현재 코드의 동작, 실제 영향을 구체적으로 설명한다. 확인되지 않은 요구사항이나 가상의 사용처를 근거로 결함을 단정하지 않는다.
- 설계는 프로젝트에서 정한 책임과 의존 방향을 기준으로 검토한다. 도메인 규칙이 Service에 흩어지는지 확인하되, 단순 조회나 변환에도 도메인 객체를 만들도록 요구하지 않는다.
- 추상화, 계층, 의존성 추가는 현재 요구사항과 구체적인 이점이 있을 때만 제안한다. 미래 가능성이나 디자인 패턴 적용 자체를 근거로 구조 변경을 요구하지 않는다.
- PR에 선택 이유와 대안이 제시되어 있으면 해당 맥락을 확인한다. 다른 구현을 선호한다는 이유만으로 변경을 요구하지 않고, 현재 선택이 놓친 조건이나 실제 비용을 설명한다.
- 테스트는 개수보다 변경된 동작과 회귀 위험을 검증하는지 살핀다. 테스트 추가를 요구할 때는 빠진 조건과 놓칠 수 있는 문제를 설명한다. 실행하지 않은 테스트를 통과했다고 표현하지 않는다.
- 리뷰 요청만으로 코드를 수정하거나 커밋하지 않는다. 개발 지침의 작업 기록 생성, 커밋, 푸시 절차는 리뷰 판단 기준과 구분한다.
- 필요한 문서나 코드에 접근할 수 없으면 그 한계를 밝히고 규칙이나 동작을 추측하지 않는다.

## 컨벤션 검토

- 정적 검사 도구로 이관하기 전까지 명시된 컨벤션 위반도 검토한다. 해당 규칙, 위치, 필요한 수정만 짧게 지적한다.
- 명시된 규칙 위반과 개인적인 개선 제안을 구분한다. 단순 컨벤션 위반을 동작 오류와 같은 심각도로 취급하지 않는다.
- 메서드 약 20줄 같은 소프트 가이드를 절대 기준으로 적용하지 않는다. 짧은 DTO 생성자 호출처럼 프로젝트에서 허용한 예외를 위반으로 지적하지 않는다.
- 같은 규칙의 반복 위반은 하나로 묶어 설명하고, 확인한 발생 위치와 건수를 함께 제시한다.

## 리뷰 작성 방식

- 간결하고 자연스러운 한국어로 작성한다. 과한 강조, 장식용 이모지, 상투적인 도입과 마무리를 피한다.
- 각 지적은 하나의 문제를 다루고, 관련 위치와 근거를 제시한다. 수정 방향은 필요한 만큼만 설명하며, 같은 원인의 문제를 반복해서 나열하지 않는다.
- 관찰한 사실과 추정을 구분한다. 확인이 필요한 사항을 확정된 결함처럼 표현하지 않는다.
- 항목을 나열할 때 가운데점 대신 쉼표를 쓴다.
- HTTP Method, HTTP 상태 코드, 오류 식별자는 인라인 코드로 표기한다.
- DB의 unique 제약은 `unique 제약`으로 표현한다.

## 컨벤션 위반 빈도 기록

- 리뷰 말미에 컨벤션 검사 범위, 검사한 파일 수, 규칙별 위반 건수, 총 위반 건수를 짧게 기록한다. PR 번호와 검토 커밋을 함께 적어 다른 리뷰와 구분한다.
- 한 규칙을 한 위치에서 위반한 경우를 1건으로 센다. 하나의 선언이나 호출에 걸친 여러 줄의 동일 위반은 1건으로 센다. 같은 위치가 서로 다른 규칙을 위반하면 규칙별로 각각 센다.
- 검사한 범위에서 위반을 발견하지 못했다면 0건으로 기록한다. 검사하지 못한 경우에는 0건으로 표시하지 않고 미검사로 기록한다.
- 재리뷰에서는 이전 지적의 잔존과 새로 발견한 위반을 구분한다. 이전 리뷰 기록을 확인할 수 없으면 신규 여부를 단정하지 않는다.
- 누적 빈도를 계산할 때 동일한 위반을 재리뷰마다 중복 집계하지 않는다. 이전 기록이 없으면 현재 리뷰의 집계만 제공한다.
- 토큰은 항상 `컨벤션 검사 토큰: 분리 측정 불가`로 기록한다. 임의의 추정치를 만들거나 전체 리뷰 사용량을 컨벤션 검사 사용량으로 표현하지 않는다.
- 리뷰 실행 환경의 출력 형식이나 보고 가능한 심각도에 제한이 있으면 그 범위 안에서 보고한다. 집계 정보를 코드 결함으로 위장하거나 컨벤션 위반의 심각도를 올려 출력하지 않는다. 집계가 출력되지 않았다는 이유로 위반이 0건이라고 해석하지 않는다.
