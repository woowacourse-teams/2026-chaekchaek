# V8 이후 기본 책장과 배치 백필

`library_shelves_after_v8.sql`은 자동 Flyway migration이 아닌 수동 실행 SQL이다.
V8이 성공한 DB에서 기존 서버의 쓰기를 중단하고 요청을 drain한 뒤 실행한다.
새 서버의 트래픽도 백필과 결과 확인이 끝날 때까지 열지 않는다.
개발은 MySQL 8.0.46, 운영은 MySQL 8.4.9를 기준으로 검증한다.

## 처리 정책

| 실행 모드 | 기본 책장 | 도서 배치 |
| --- | --- | --- |
| `development` | 기존 기본 책장 재사용, 없으면 단일 기존 책장 승격, 기존 책장도 없으면 생성 | V8이 복사한 배치와 순서를 그대로 보존 |
| `production` | 기존 기본 책장 재사용, 없으면 현재 닉네임과 같은 이름의 책장 승격, 없으면 생성 | 활성 회원의 기존 기록을 기본 책장에 배치하고 승인한 초과분을 추가 책장으로 분배 |

- 책장이 없는 활성 회원은 도서가 없어도 기본 책장을 만든다. 닉네임이 `NULL`, 빈 문자열, 공백뿐이면 이름은 `기본 책장`이다. 회원 닉네임 자체는 변경하지 않는다.
- 기존 책장의 ID, 이름, 표시 순서, 생성과 수정 시각은 유지한다. 새 책장은 회원의 맨 뒤에 추가한다. 새 입력의 10자 규칙으로 기존 이름을 잘라내거나 보정하지 않는다.
- 운영에서 이름이 다른 기존 일반 책장은 유지하고, 새 기본 책장을 맨 뒤에 추가한다. 같은 이름 비교는 DB collation을 따른다.
- 개발에서 기본이 없는 회원의 기존 책장이 여러 개면 자동 선택하지 않고 중단한다.
- 비활성 회원의 기존 책장, 배치와 기록은 보존하고 새 책장과 배치를 만들지 않는다.
- 공유 기록의 ID, 독서 상태, 페이지, 별점과 모든 기존 시각은 변경하지 않는다. 실행 중 원본과 대조한다.

### 운영의 승인된 초과 회원

| 회원 ID | 확인한 기록 수 | 기본 책장 | 추가 책장 |
| --- | --- | --- | --- |
| `1` | 37 | 30권 | 7권 |
| `20` | 36 | 30권 | 6권 |

두 회원의 기록 수나 활성 상태가 바뀌었으면 중단한다. 다른 활성 회원이 30권을 초과해도 중단한다.
변경된 데이터를 확인하고 승인 범위를 갱신한 뒤 SQL과 검증을 함께 수정한다.
삭제 완료된 회원 `5`의 기록은 다시 만들지 않는다. 회원 `5`가 활성 회원이면 빈 기본 책장은 생길 수 있다.

도서 순서는 회원별 `reading_updated_at DESC`, `book_id DESC`다.
앞 30권은 기본 책장, 초과분은 추가 책장에 넣고 각 책장의 순서는 `1`부터 시작한다.
추가 책장 이름은 `추가 책장`이며 기본 책장과 이름이 같으면 `추가 책장 2`를 사용한다.
이미 같은 이름의 일반 책장이 있으면 재사용한다. 그 책장의 기존 배치가 계획과 다르면 중단한다.

## 실행 순서

1. 전환 전 백업을 확보하고 실제 접속 대상, 최신 기록 수와 스키마를 확인한다.
2. 구 서버의 쓰기를 중단하고 진행 중 요청을 drain한다. 새 서버에도 트래픽을 보내지 않는다.
3. 호환 앱 코드와 같은 PR의 V8을 Flyway로 적용한다. V8의 DDL은 전체 롤백이 불가능하므로, 실패했다면 스키마와 Flyway 이력을 확인하고 복구 계획을 정한다.
4. DB에 접속할 수 있는 머신으로 이 SQL을 복사하고 아래 명령을 실행한다.
5. 성공 결과를 확인한 뒤 새 서버로 전환한다. 새 배치 쓰기를 시작한 후 구 서버로 단순 롤백하지 않는다.

아래는 OS 셸 명령이다. `mysql>` 프롬프트에서는 `exit` 후 실행한다.
`DB_HOST`, `DB_USER`, 파일의 절대 경로를 실제 값으로 바꾼다. 비밀번호는 프롬프트에서 입력한다.
DB 이름이 다르면 `--database`도 바꾼다.

개발:

```sh
BACKFILL_SQL=/absolute/path/library_shelves_after_v8.sql
mysql --default-character-set=utf8mb4 --host=DB_HOST --user=DB_USER --password --database=chaekchaek \
  --batch --skip-reconnect --init-command="SET @library_backfill_mode='development'" \
  < "$BACKFILL_SQL"
```

운영:

```sh
BACKFILL_SQL=/absolute/path/library_shelves_after_v8.sql
mysql --default-character-set=utf8mb4 --host=DB_HOST --user=DB_USER --password --database=chaekchaek \
  --batch --skip-reconnect --init-command="SET @library_backfill_mode='production'" \
  < "$BACKFILL_SQL"
```

**한 번의 배치 연결로 전체 파일을 실행하고 `--force`를 붙이지 않는다.**
기본 동작의 mysql 배치 실행은 SQL 오류에서 종료되며, 연결이 닫히면 아직 커밋하지 않은 백필 DML이 롤백된다.
대화형 `SOURCE`, GUI에서 오류 후 계속 실행, 명령문 일부만 복사하는 방식은 사용하지 않는다.
마지막 검사를 모두 통과해야 `COMMIT`에 도달한다. 실패 시 오류와 종료 코드를 보존하고 원인을 확인한다.
백필의 롤백 범위에는 앞서 별도로 실행한 V8의 DDL이 포함되지 않는다.

## 성공 결과와 재실행

마지막 결과의 `active_members`와 `active_default_libraries`가 같아야 한다.
운영은 `active_records`와 `active_placements`가 같고, 회원 `1`, `20`의 배치 수가 위 표와 같아야 한다.
개발은 기존 배치를 유지하므로 기록과 배치 수가 같다는 비교보다 원본 보존 검사를 따른다.
SQL 내부에서 활성 회원의 기본 책장 누락, 배치 누락, 공유 기록과 기존 책장/배치 변경, 비활성 회원에 대한 새 배치를 검사한다.

같은 쓰기 중단 구간에서 같은 이전 데이터를 대상으로 재실행할 수 있다.
기존 배치의 ID와 순서를 덮어쓰지 않고 누락된 배치만 추가한다. 새 앱의 정상 쓰기가 시작된 뒤 반복 실행하는 동기화 SQL은 아니다.
기존 운영 배치가 계산한 대상 책장이나 순서와 다르면 임의로 이동하거나 순서를 바꾸지 않고 전체 백필을 중단한다.

검증 재현은 비밀번호 없는 root를 사용하는 격리된 로컬 MySQL 컨테이너에서 한다.
실제 개발/운영 DB나 SSH 터널 포트를 테스트 환경 변수로 지정하지 않는다.

```sh
MYSQL_MIGRATION_TEST_PORT=13309 ./gradlew test --tests '*LibraryShelfBackfillTest' --no-daemon
```
